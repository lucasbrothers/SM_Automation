# Windows CLIENT 에이전트: IP·포트만 입력하는 설치

## 설치하는 사람

1. 관리자가 GUI **Windows CLIENT 설치 / 상태 → 설치 파일 저장 / 등록 허용**에서 만든 `SM-Windows-Client-Setup.exe`를 전달받습니다.
2. Windows CLIENT에서 실행하고 최초 관리자 권한 요청을 승인합니다.
3. **Linux SERVER IP 또는 DNS와 통신 포트 두 항목만 입력**하고 **설치 및 연결**을 누릅니다. 기본 통신 포트는 `7443`입니다.
4. 서비스가 자동 시작하고 장비별 RSA 인증 정보를 생성해 SERVER에 자동 등록합니다. 성공하면 설치 화면에 자동 등록 완료가 표시됩니다. 네트워크 장애나 등록 기간 만료 시 설치는 유지하고 연결을 재시도합니다.

CLIENT에서 SSH/OpenSSH·WinRM·Python 설치, 계정/비밀번호 입력, 공개키 수동 배포, 인증서 수동 설치, 인바운드 방화벽 규칙 추가는 필요 없습니다. 설치 파일은 Windows 기본 .NET Framework 4.7.2 이상과 Windows PowerShell이 있는 데스크톱 환경을 대상으로 합니다(Windows Server 2019 이후 Desktop Experience/Windows 11 등). AppLocker·WDAC·백신·아웃바운드 정책은 우회하지 않으며 조직 정책에 따라 실행 허용이 필요할 수 있습니다.

```text
Windows CLIENT ── 먼저 접속하는 TLS 통신 ──> Linux SERVER : 7443
Windows GUI    ── 기존 앱 로그인/TLS     ──> Linux SERVER : 7443
```

현재 통신은 기존 전용 TLS 프로토콜이며 HTTPS API가 아닙니다. 중간에 HTTPS 전용 프록시가 있으면 별도 TCP 전달 구성이 필요합니다. SERVER IP/DNS는 고정 주소를 사용하세요. Windows 서비스 이름은 `SMAutomationAgent`, 표시 이름은 `SM Automation Windows Agent`입니다. 로그인 전에도 자동 시작하고 GUI가 꺼져도 동작합니다.

## Linux SERVER / GUI 관리자

Linux SERVER와 Windows GUI를 새 버전으로 업데이트합니다. Linux 서버의 기존 TLS 포트를 사용하므로 별도 CLIENT 수신 포트나 별도 서버 포트를 추가하지 않습니다.

GUI 왼쪽 **Windows CLIENT 설치 / 상태**에서 다음을 지정합니다.

- **등록 허용 출발지 CIDR**: 실제 SERVER가 보는 CLIENT 출발 IP/네트워크. NAT를 쓰면 NAT 이후 주소입니다. 기본 후보는 사설 네트워크이며 운영에서는 실제 관리망으로 좁히세요.
- **허용 기간**: 기본 24시간, 최대 168시간.
- **신규 등록 수**: 기본 1,000대, 최대 5,000대이며 전체 관리 목록 상한도 5,000대입니다.
- **설치 파일 저장 / 등록 허용**: 접속 중인 SERVER의 공개 인증서 지문을 설치 파일에 넣고 신규 등록을 허용합니다. 파일 안에 관리자 비밀번호·공용 등록 토큰·장비 개인키를 넣지 않습니다. CLIENT 사용자는 IP/포트만 입력합니다.
- **신규 등록 닫기**: 신규 등록만 중지합니다. 등록된 장비는 기존 장비 인증으로 계속 연결됩니다.

SERVER 신규 등록은 기본적으로 닫혀 있습니다. 설치 파일은 SERVER별로 생성하며, 다른 Linux SERVER에 배포한 뒤에는 그 SERVER GUI에서 파일을 다시 생성해야 합니다. 서버 인증서가 바뀌면 기존 지문이 일치하지 않아 연결을 거부하므로 새 인증서가 반영된 설치 파일로 설정을 갱신해야 합니다. 운영 중인 장비는 정상 설치 파일 재실행 시 기존 장비 인증을 유지합니다.

등록 기간 안의 허용 네트워크에서 장비가 키 소유를 증명하면 **사람의 개별 승인 없이 등록**됩니다. 이것은 회사 소유 장비의 하드웨어 신원 검증/TPM attestation이 아닙니다. 같은 허용 망의 임의 장비도 등록을 시도할 수 있으므로 등록 망·기간·수량을 좁히고 배포 후 신규 등록을 닫아야 합니다. 미등록 장비는 출발 IP당 분당 120회 도전 요청 제한이 있어 대량/NAT 배포는 시차를 두세요.

서버 인증은 설치 파일에 포함된 공개 인증서 지문과 인증서 유효 기간으로 확인합니다. 지문이 없는 원본 개발 설치 파일은 Windows 신뢰 저장소와 이름 검증을 통과하는 SERVER만 연결합니다. 인증서 검증을 무조건 통과시키는 모드는 없습니다.

## 자동 추가 및 관리

최초 연결 후 hostname·대표 IP·OS·CI가 서버에 자동 추가됩니다. 같은 이름의 기존 장비는 덮어쓰지 않고 `-agent-장비ID`를 붙인 새 항목을 만듭니다. 이름/IP만으로 기존 장비 인증을 탈취하거나 SSH 대상의 접속 방식을 바꾸지 않습니다. 일반 관리 목록은 약 30초마다 새 장비를 확인하고, 새 장비는 전체 목록에 추가되며 기존 장비록에 임의로 포함하지 않습니다.

장비별 식별/개인키는 CLIENT에서 생성하고 `%ProgramData%\SM Automation Agent\identity.bin`에 Windows DPAPI로 보호합니다. 폴더 접근 권한은 SYSTEM/관리자로 제한합니다. SERVER에는 공개키와 장비 식별 정보만 보관하고, 기존 암호화 저장소 `DATA/agents/`를 사용합니다.

에이전트는 약 30~35초 간격으로 SERVER 작업을 확인하고 CI는 시작 시와 약 15분 간격으로 수집합니다. 작업이 있으면 결과를 즉시 전송합니다. 네트워크 장애에는 지연을 늘려 재시도합니다. SERVER는 장비별 작업을 내구성 있게 저장하며, CLIENT는 실행 시작/결과를 기록해 재시작 후 변경 명령을 무조건 반복하지 않습니다. 실행 중 중단된 작업은 완료 여부 불명으로 보고합니다.

| Windows agent 지원 | 내용 |
|---|---|
| CI | OS·하드웨어·CPU/메모리/GPU·uptime·SMT 등 자동/요청 수집 |
| 연결 조회 | 기존 Connection map / TCP 연결 목록 |
| 명령 실행 | 09 메뉴의 **PowerShell 명령**, LocalSystem 권한, 최대 8,000자·90초·출력 약 1MiB |
| CLIENT↔SERVER 파일 | 일반 파일 최대 8MiB, 체크섬 검증, 기존 파일 덮어쓰기/링크 거부 |
| 장비록 | 기존 장비록에 수동 포함한 뒤 해당 단위로 지원 작업 실행 |
| 아직 미지원 | Windows agent 백업/설정 비교, Linux 전용 계정/패치/보안/08 자원 모니터링 |

기존 Linux/AIX/Windows SSH 경로는 유지합니다. Windows agent의 `09` 명령은 Linux shell/root 명령이 아니며 PowerShell 문법을 사용합니다. 설치 서비스는 **LocalSystem**으로 동작하므로 SERVER 관리자 권한이 해당 Windows의 강한 제어 권한으로 이어집니다. 운영 전에 GUI 초기 비밀번호 변경, SERVER 접근 제한·역할 분리·서버 키 보호가 필요합니다. 운영자/조회자는 원격 SYSTEM 명령을 제출할 수 없습니다.

## 제거·오프라인·목록 삭제

CLIENT에서 **Windows 앱/프로그램 제거 → SM Automation Windows Agent**를 제거하거나 설치 파일의 **클라이언트 제거**를 누릅니다. 서비스 중지·삭제, 가능한 경우 서명된 제거 통보, 장비 개인키/설정 삭제를 수행합니다. 실행 중인 제거 도구 자체는 Windows 재부팅 시 정리될 수 있지만 서비스는 이미 중지/제거됩니다. 자동으로 재부팅하지 않습니다.

SERVER GUI **Windows CLIENT 설치 / 상태**에서 상태와 마지막 접속 시각을 확인합니다.

- **접속 중**: 마지막 정상 접속이 120초 이내.
- **오프라인**: 120초 이상 정상 접속 없음. 전원 종료·네트워크 장애·강제 삭제를 구분할 수 없으므로 제거 확정으로 표시하지 않습니다.
- **제거됨**: 정상 제거 통보를 수신. 해당 장비 인증은 더 이상 허용하지 않습니다.
- **접속 차단**: 관리자가 장비 인증을 폐기.
- **목록에서 제거**: 관리자가 선택하면 관리 목록에서 제거하고 장비 인증을 폐기합니다. CI/작업 이력은 보존하며 제거된 인증으로 자동 재등록하지 못합니다. 재설치로 새 개인키가 생긴 장비는 신규 등록 정책을 다시 따릅니다.

이미 CLIENT에 전달되어 실행 중인 명령은 SERVER 목록 제거만으로 소급 취소되지 않을 수 있습니다. CLIENT 서비스를 제거하면 해당 서비스가 실행한 프로세스 트리의 종료를 시도합니다.

## 배포 파일·검증 범위

`release/SM-Windows-Client-Setup.exe`는 현재 로컬 WSL SERVER의 공개 인증서 지문으로 만든 실습용 설치 파일입니다. 운영 SERVER용 파일은 해당 SERVER에 연결한 최신 GUI에서 생성하세요. `.sha256` 파일로 전달 중 파일 변경 여부를 확인할 수 있습니다. 현재 개발 빌드는 조직 코드 서명이 없으므로 운영 배포 전 코드 서명/조직 실행 정책 검토가 필요합니다.

빌드: Windows 개발 PC에서 `python scripts/build_windows_agent.py`를 실행하면 Windows 기본 .NET Framework 컴파일러로 에이전트와 설치 파일을 만듭니다. 개발/빌드 PC의 Python은 필요하지만 설치 대상 CLIENT의 Python은 필요 없습니다.

자동 검증은 컴파일된 Windows 실행 파일의 암호·통신 시험 모드와 독립 로컬 WSL TLS 서버를 연결해 잘못된 인증서 지문 거부·자동 등록·CI·작업/결과 전달·제거 통보·인증 폐기를 확인합니다. 통신 시험은 가짜 장비 정보와 고정된 무해한 출력 명령을 사용하며 Windows 서비스 설치나 OS 설정 변경을 하지 않습니다. 실제 Windows의 서비스 설치/자동 부팅/앱 제거는 아직 실행 검증하지 않았습니다. 운영 Windows 장비와 실제 1,000대 동시 접속 부하 시험도 남아 있습니다.
