# CI 자산 관리

Windows GUI의 **10 CI / 자산**에서 관리합니다. hostname·관리 IP·OS 및 SSH 접속 정보는 기존 CLIENT 목록과 CLIENT login settings를 사용합니다.

1. 상단 실행 대상에서 장비록을 선택하거나 Connection map에서 CLIENT를 선택합니다.
2. **선택 / 장비록 정보 수집**을 누릅니다. CI 목록에서 행을 선택했다면 해당 행만 수집하며, 행 선택이 없으면 상단 실행 대상을 사용합니다. 작업 진행은 Activity에서 확인합니다.
3. **조회**로 저장된 자산 정보를 확인합니다. 전체 장비 또는 현재 장비록으로 범위를 좁히고 hostname/IP/고객사/서비스명 등으로 검색할 수 있습니다.
4. 행을 선택한 뒤 **선택 장비 개별 / 일괄 편집**을 누릅니다. 여러 행은 Ctrl/Shift로 선택합니다. **조회 전체 일괄 편집**은 현재 검색·상태·장비록 필터에 맞는 모든 페이지의 장비를 수정합니다.
5. 변경할 속성만 체크해 입력합니다. 체크하지 않은 속성은 유지하며, 체크 후 빈 값으로 저장하면 해당 값이 지워집니다. 자동 수집 속성은 직접 수정하지 않습니다.
6. **상세 보기** 또는 행 더블클릭으로 전체 수집값·참고사항·오류·최근 성공/시도 시각을 봅니다. **조회 전체 CSV / Excel 저장**은 현재 필터에 맞는 모든 페이지와 전체 속성을 저장합니다.

## 자동 수집

대표 IP(기본 경로의 인터페이스 우선), 관리 IP와 전체 IP, 실제 hostname, OS 종류·버전, 커널·아키텍처, 제조사·모델·serial·UUID, CPU 모델·보이는 논리 CPU·물리 core, 할당 vCPU 상한, OS/할당 메모리 GiB, GPU, uptime, 부팅 시각, 가상화 정보를 수집합니다. 플랫폼마다 제공되는 값은 다릅니다.

- Linux: `/etc/os-release`, `/proc`, DMI sysfs, 기본 경로/IP, 기존 GPU 탐지 도구를 읽습니다. DMI serial/UUID가 일반 계정에서 보이지 않으면 기존 로그인 비밀번호를 사용한 sudo 읽기를 시도합니다. root 비밀번호를 별도로 요청하거나 저장하지 않습니다. sudo가 불가능하면 미확인으로 남깁니다.
- Linux 할당 CPU는 OS 논리 CPU·프로세스 affinity·확인 가능한 cgroup v2 자신 및 상위 CPU quota의 최솟값입니다. 메모리는 OS 값과 확인 가능한 cgroup v2 계층 제한의 최솟값입니다. v1/숨겨진 계층·별도 스케줄러 제한은 완전히 확인할 수 없으므로 참고사항과 실제 플랫폼 설정을 확인하세요. CPU shares는 예약 core 수와 다릅니다.
- Windows SSH: PowerShell CIM으로 OS·BIOS·컴퓨터 시스템·CPU·GPU·네트워크·부팅 시각을 조회합니다. Windows job/container의 별도 제한은 수집하지 않습니다.
- AIX SSH: oslevel/prtconf/lparstat/ifconfig/uptime으로 LPAR에 노출된 값을 수집합니다. CPU entitlement는 참고사항에 별도로 표시합니다. 물리 host core를 LPAR 할당 core로 간주하지 않습니다.
- VM/컨테이너에서는 guest에 노출된 정보입니다. 하이퍼바이저의 실제 물리 서버 정보라고 단정할 수 없습니다.
- GPU 도구가 없거나 serial 등 권한이 부족하면 **미확인/미수집**으로 표시합니다. GPU 탐지 결과가 비어 있어도 GPU가 없다고 단정하지 않습니다. 패키지를 자동 설치하지 않습니다.

고객사·운영상태(운영/유휴/폐기)·서비스 등급·담당자·서비스명 외에 자산번호, 위치/랙, 환경, 용도, 유지보수 업체, 도입일, 유지보수 종료일, 메모를 저장합니다. 날짜는 YYYY-MM-DD 형식입니다.

## 저장·권한·부하

모든 자산 정보는 Linux SERVER `DATA/ci/`의 장비별 암호화 파일에 저장됩니다. GUI를 종료해도 유지됩니다. 재수집은 직접 입력한 정보를 변경하지 않으며, 접속 실패 시 마지막 성공값과 시각을 보존하고 실패 상태를 함께 표시합니다. 관리 IP가 바뀌면 재수집 필요 표시가 나옵니다. CLIENT 목록에서 삭제한 장비의 CI 파일은 보존되지만 현재 목록에서는 제외됩니다.

관리자만 자산 속성을 변경할 수 있습니다. 운영자와 관리자는 수집 작업을 실행하고, 조회자는 저장된 정보만 조회·내보내기할 수 있습니다. 조회 전체 편집의 저장 실패는 장비별로 보고하며 부분 성공이 가능합니다.

화면은 100대씩 조회하고 파일 저장은 200대 단위로 읽습니다. 명시적으로 수집을 실행할 때만 SSH 접속합니다. 기존 전역 동시 SSH 제한과 50대 초과 시 시작 분산을 공유하며, 작업 상세는 장비별 암호화 파일로 분리합니다. 현재 검색 결과의 전체 편집/내보내기는 조회 중에 다른 사용자가 수정할 경우 단일 시점 스냅샷을 보장하지 않습니다.

로컬 WSL Ubuntu 실제 SSH/TLS 수집과 Windows GUI 검증을 완료했습니다. 외부 Windows/AIX/RHEL 실제 장비와 1,000대 실접속 부하 시험은 수행하지 않았습니다.
