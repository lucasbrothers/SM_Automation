# Logger 구현 및 검증 완료

검증일: 2026-09-17

이전 대화의 L-28 이후 상세 답변은 복원되지 않았으므로 단계 번호를
추정하지 않고 현재 소스와 테스트를 기준으로 남은 작업을 수행했다.

## 순서별 완료 내역

1. 기존 테스트 실행: 48개 통과.
2. 테스트 격리: 테스트마다 별도 singleton과 임시 로그 디렉터리를 사용하고
   종료 시 핸들러를 해제한다. 실제 운영 로그와 이전 테스트 출력에 의존하지 않는다.
3. 민감정보 처리: JSON·딕셔너리 형태의 키, 따옴표 안의 공백이 포함된 값,
   Basic/Bearer 인증, PEM 개인키를 마스킹한다. 예외 객체를 재생성하지 않고
   출력 텍스트를 마스킹하여 사용자 정의 예외와 원인 체인을 보존한다.
4. 로그 무결성: 개행뿐 아니라 탭, NUL, ESC, C1 제어문자와 Unicode 줄 구분자를
   이스케이프한다. Context의 추가 제어문자도 거부한다.
5. 생명주기: 초기화와 핸들러 구성을 잠금으로 보호하고, 초기화 실패 후
   재시도가 가능하도록 상태를 설정한다. 파일 핸들러 생성 실패 시 콘솔
   핸들러를 정리한다. 프로젝트 디렉터리 이름을 변경해도 루트를 찾는다.
6. 회귀 검증: 최초 동시 초기화, 중복 출력 방지, 초기화 실패 후 복구,
   예외 캐시·스택 마스킹, UTF-8 파일 회전과 백업 개수를 확인했다.

## 최종 결과

```powershell
.venv/Scripts/python.exe -m pytest -q -p no:cacheprovider
```

**73 passed** — 기존 48개와 추가 25개가 통과했다.
이 환경에서는 pytest 기본 임시 폴더의 접근 제한 때문에 권한이 승인된
실행 환경에서 검증했다.

기존 인터페이스 `get_logger(name, context)`, INFO 기준 출력,
10 MiB 단위 파일 회전 및 백업 30개 설정은 유지한다.
마스킹은 구현된 키·인증 형식에 적용되며 임의의 비밀 문자열을 자동으로
식별하는 기능은 아니다. 동시성 검증 범위는 단일 프로세스의 여러 스레드다.
프로그램 종료는 로그를 생성하는 작업이 끝난 뒤 호출한다.
