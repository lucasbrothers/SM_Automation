# 다른 PC에서 개발 이어가기

기준: 2026-10-08 아키텍처 변경. 이 문서가 2026-09-17 인계보다 우선한다.
저장소: https://github.com/lucasbrothers/SM_Automation / 브랜치: master

## 이번에 변경한 방향

1. Linux가 메인 서버이며 모든 실제 업무를 수행한다.
2. Windows는 네이티브 GUI/통제만 담당하고 전용 TLS/TCP 7443으로 연결한다(SSH 터널 아님).
3. 관리 대상 접속은 SSH를 유지한다. Windows 대상도 OpenSSH를 사용한다.
4. PostgreSQL을 제거하고 DATA/BACKUP의 내용을 암호화한다.
5. 체크박스·전체선택 + netstat ESTABLISHED 마인드맵, 전체 대상 OS별 백업을 추가했다.
6. 후속 사용자 지시로 로컬 WSL Ubuntu 통합 테스트를 승인받았다. 결과와 재개 방법은 docs/wsl-progress.md를 따른다.

## 새 PC 준비

```sh
git clone https://github.com/lucasbrothers/SM_Automation.git
cd SM_Automation
git switch master
```

이미 저장소가 있다면 로컬 변경을 보존한 뒤 `git pull --ff-only origin master`로 갱신한다.
가상환경은 복사하지 않는다. Linux 서버는 requirements-runtime.txt,
Windows GUI는 requirements-gui.txt를 사용한다. 이번 GUI 렌더링 환경은 Windows / Python 3.14.7 / PySide6 6.11.2다.
로컬 WSL Ubuntu에서 root Linux 서비스를 실행하고 Windows GUI 연동을 확인했다. 폐쇄망 패키지는 대상 OS·Python과 일치하도록 별도 준비한다.

새 설치는 deployment.md대로 Linux에서 키와 인증서를 생성한다.
기존 DATA/BACKUP을 이어받는 경우 원래 master.key가 반드시 필요하다.
Git에는 실제 키·토큰·운영 CSV·DATA·BACKUP·가상환경이 포함되지 않는다.
기존 PostgreSQL의 운영 데이터를 파일로 변환하는 마이그레이션은 별도 작업이다.
DB 소프트웨어를 이 PC에서 제거하거나 DB 데이터를 삭제하지는 않았다.

## 다음 PC에서 최소 확인할 항목

로컬 WSL에서는 1~4의 핵심 경로를 확인했다. 다른 PC에서는 다음 기능의 정상 여부 위주로 재확인한다.

1. Linux 서비스를 시작하고 Windows가 TLS 7443으로 인증·접속하는지.
2. GUI에서 서버 목록을 저장하고 Linux DATA의 파일이 암호화되는지.
3. 서버 1대 선택/전체선택 후 netstat 연결이 맵과 표에 표시되는지.
4. Linux 1대의 sudoers/sudoers.d, 계정별 chage 결과와 manifest를 읽을 수 있는지.
5. AIX 및 Windows OpenSSH 대상에서 OS별 명령과 인코딩/권한이 맞는지.
6. GUI 종료 후 Linux 작업이 계속되고 재접속하여 이력을 읽을 수 있는지.

기존 pytest를 원하면 requirements-dev.txt 설치 후 실행하되 이번 기능의 충분한 검증으로
간주하지 않는다. 기존 설정 테스트의 PostgreSQL 기대값만 새 설정에 맞춰 수정했고 새 대규모
테스트는 추가하지 않았다. 이전 101 passed 기록은 이전 코드 기준이다.

## 현재 구현의 한계 / 이어서 할 작업

- 최신 사용자 지시로 Red Hat Enterprise Linux를 명시적으로 지원 범위에 추가했다. RHEL은 Linux 공통 기능과 RPM/DNF 캐시 업데이트 조회·버전 고정 계획·백업 후 로컬 서명 RPM 적용 경로를 사용한다. 실제 RHEL 검증은 아직 필요하다. 외부 대상 테스트는 승인되지 않았고 현재 테스트는 로컬 Ubuntu WSL만 사용한다.

- 서버별 SSH 프로필을 추가했다. Linux의 보호된 ssh-profiles.json에 계정/키/포트를 정의하고 GUI/CSV에는 profile 이름만 지정한다. 다른 PC에서 실제 연결을 확인한다.
- AIX/Windows 실환경 netstat 및 파일/명령 수집 조정.
- Linux 계정 GUI와 변경 전 암호화 백업을 구현하고 WSL에서 확인했다. Debian/Ubuntu 및 RHEL 패치 조회·계획·백업 후 적용 경로를 연결했다. SSH 설정 파일 권한 600 및 인증 정책 계획/적용을 추가했다. 전역 Include 적용·실패 복구를 WSL에서 확인했다. 조건부 Match 및 AIX/Windows 계정·패치는 후속 범위다. RHEL 적용 실환경 검증은 별도로 필요하다.
- API는 공통 운영자 토큰 방식. 예약 수집/백업과 대기 대상 취소를 구현했다. 사용자별 로그인·역할 및 실행 중 원격 명령 강제 취소는 후속 범위.
- 수집 결과는 서버당 5,000 연결, 그래프는 서버당 25 peer로 제한. 대용량 최적화는 후속 범위.
- 백업 전체 복원과 대용량 스트리밍, 키 순환, 보존기간 정리 기능은 후속 범위.
- 기존 직접 실행 스크립트는 과거 호환 도구이며 새 GUI의 운영 경로가 아니다. 새 기능은 run_server.py를 통해 사용한다.
- Linux 계정 공개키 등록을 추가했다. 개인키는 받지 않으며 등록 전 authorized_keys 상태도 암호화 백업한다. Python 3가 필요하고 실제 검증은 로컬 WSL만 수행했다.
- SSH 설정 적용은 sudo 프로필 또는 direct root를 지원한다. direct root의 적용·재접속·복구·임시 정리에는 sudo가 필요하지 않다. WSL에서 적용 및 실패 복구를 확인했다.
- Red Hat 인증 설정 백업에 SSSD·Kerberos·sudo 전역 설정을 포함했다. 없는 선택 경로는 경고로 남긴다. 실제 RHEL 수집은 후속 확인이 필요하다.
- 백업 이력은 전용 필터로 100건씩 이전 기록을 조회한다. 서버 재시작 시 전체 암호화 이력을 복원하며, 미완료 작업은 자동 재실행하지 않는다.
- Activity의 Load older operations에서 백업 외 작업 이력도 100건씩 더 읽는다. 연결을 해제하면 GUI 캐시는 초기화하며 Linux 이력은 보존한다.
- 서버 목록 편집은 Linux SSH 프로필 이름 선택 목록을 사용한다. docs/images/inventory-mockup.png에 합성 예시를 보관했다. CSV/API/직접 가져오기에서 공통 입력·프로필 검사를 사용한다.
- 연결 맵은 성공 0건·실패·취소 대상을 구분한다. 맵/표에서 서버명·IP 및 로컬/원격 주소·포트를 검색할 수 있다.

전체 백업 복원·사용자별 역할·키 순환·보존기간 자동 정리는 위에 명시된 후속 범위이며 현재 요청의 기본 수집/백업 완료와 구분한다.

다른 PC용 scripts/start_desktop.ps1을 추가했다. -Check는 설치 환경 확인, -Demo는 합성 화면 실행이며 인증정보를 저장하지 않는다.
다음 점검 후보는 실행 중인 Linux 방화벽 규칙 수집이다. 구현할 경우 도구 부재와 실제 실패를 구분하고 기존 백업 항목 수를 가정한 확인 스크립트도 함께 조정한다. 외부 대상 테스트를 추가 승인 없이 확대하지 않는다.

## 2026-10-09 방화벽 실행 상태 수집

Linux 백업에 현재 nft/IPv4·IPv6 iptables 규칙을 추가했다. 없는 도구와 수집 실패를 구분하며 전체 도구 부재는 성공으로 처리하지 않는다.
실제 WSL TLS/GUI 검증 통과. 백업은 12개 항목이며 nft 진단이 있는 경우 부분 완료와 원문을 보존한다. GUI 검증은 고정 항목 수 대신 실제 결과와 firewall 존재를 확인한다.

방화벽 후속 수정: nft -j list ruleset으로 JSON 규칙을 저장한다. 최신 WSL 실제 백업 12개 항목 모두 completed이며 앞선 partial은 이전 텍스트 출력의 진단 결과다. 실제 명령 실패는 계속 부분 완료로 보존한다.

추가 진단: 명령 그룹·방화벽·계정 진단은 명령/계정명과 원래 종료 코드로 조용한 실패도 표시한다. 관련 WSL 검증 14개와 실제 TLS 백업 12개 항목 완료 확인을 진행했다.

Unix 설정 백업은 끊어진 심볼릭 링크도 보존한다. WSL tar 확인을 포함한 관련 검증 15개와 실제 TLS 백업 12개 항목 완료 확인 통과.

설정 아카이브 미리보기에서 링크 종류와 대상 경로를 확인할 수 있다. 링크 제어 문자 표시 검증 2개 및 실제 WSL TLS 통합 확인 통과.

이력 복구는 JSON 필드 타입도 검사한다. 잘못된 status/시간/종류/결과 목록은 원본을 보존한 복구 필요 상태로 처리하며 정상 이력을 계속 읽는다. WSL 검증 11개 및 실제 TLS 통합 통과.

손상된 schedules.json.enc도 원본을 보존한 복구 필요 상태로 처리한다. 서버 조회는 유지하고 새 작업/예약은 차단하며 자동 실행/원본 덮어쓰기는 하지 않는다. 예약·이력 WSL 검증 26개와 실제 TLS 통합 확인 통과.

예약 복구에서 실행 hosts와 저장 targets의 서버명 일치 및 중복 여부를 검사한다. 불일치는 원본 보존 복구 상태로 처리한다. 관련 검증 29개와 실제 WSL 예약 통합 확인 통과.

예약 화면은 새로고침에서 Linux 실행기 상태도 확인해 중단/복구 차단을 표시한다. 실행기 실패는 예외 종류만 기록한다. 관련 화면 22개·예약 18개 및 실제 WSL GUI 통합 확인 통과.

예약 상태 문구/dispatching/이전 작업 참조 형식도 검사한다. 실행기 상태 표시 3개 분기를 포함한 화면 검증 25개·예약 검증 21개 및 실제 WSL 예약 통합 확인 통과.

예약 실행기가 오류로 중단된 동안 새 예약/재개는 거부하고 복구 후 재시작을 안내한다. 일시정지·삭제는 허용한다. 관련 검증 22개와 실제 WSL 예약 통합 확인 통과.

Linux 암호화 저장은 파일 교체 후 디렉터리 기록도 동기화한다. 동기화 실패는 저장 오류로 전달한다. 관련 검증 35개 및 실제 WSL 예약 재시작/TLS 백업 확인 통과. 전원 장애 실험은 수행하지 않았다.

예약 API 저장 실패도 실행기를 중단한다. 실패한 일시정지 뒤 메모리상 활성 예약이 실행되지 않음을 확인했다. 관련 검증 23개 및 실제 WSL 예약 통합 통과. 동기화 실패는 저장 여부가 불확실하므로 재시작 전 Linux 예약/이력을 확인한다.

암호화 저장/방화벽 수집 보완 이후 실제 WSL 계정·공개키·만료·그룹·잠금·삭제와 사전 백업, 패치 정확 버전 계획/변경 없는 적용을 확인했다. 임시 계정 삭제·홈 보존. 실제 RHEL 적용은 미검증.

작업 이력의 알 수 없는 상태·잘못된 진행 수치·문구 형식을 복구 대상으로 분류한다. 원본 보존 확인을 포함한 검증 17개 및 실제 WSL TLS 백업 12개 항목 완료 확인 통과.

## 2026-10-12 09 명령 root 전환

09 명령은 Linux/AIX CLIENT에서 root 실행한다. root 로그인은 직접 실행하고 그 외는 sudo -S로 로그인 비밀번호를 stdin 전달한다. root 확인 표시가 나오기 전에 전환이 실패하면 입력한 root 비밀번호로 su를 재시도한다. 명령이 시작된 뒤 비정상 종료한 경우에는 중복 실행하지 않는다. su는 PTY echo를 끄고 Password 프롬프트 뒤에만 비밀번호를 전송한다. root 비밀번호는 작업 메모리에서만 유지하고 이력/옵션/문서에 저장하지 않으며 종료 후 제거한다. 명령 stdin은 /dev/null로 분리한다.
기존 화면·SSH 검증 37개, 전환 분기 검증 2개 및 로컬 WSL 직접 root 실행 통과. 실제 비밀번호 sudo/su 전환은 아직 미검증이며 유효한 CLIENT SSH 접속 설정이 필요하다. 자동화 일시정지 유지.

Canonical Ubuntu noble cloud 이미지 공식 SHA256 확인, D:/WSL/Ubuntu-Client-VM/Ubuntu-Client-30G.vhdx 준비(virtual-size 32212254720, 실제 약 2.04GiB). 최초 qemu VHDX resize 미지원으로 작업용 qcow2를 30GiB 확장한 뒤 VHDX로 변환했고 잘못된 중간 디스크는 정리했다. seed.iso에는 SERVER의 기존 SSH 공개키만 포함, D25950/sds 키 로그인 및 sudo 설정을 준비했다. 비밀번호/개인키는 문서·Git·seed에 저장하지 않았다. qemu-utils/cloud-image-utils와 6개 의존 패키지 약 14.7MB 설치. WSL 외부 저장소 접속이 실패해 Windows에서 공식 Ubuntu 패키지를 가져오고 기존 APT 메타데이터 SHA256과 대조하여 dpkg로 설치했다. 기존 SERVER 서비스를 변경/재시작하지 않았다.

VM/네트워크 생성 스크립트는 D:/WSL/VM-Setup/Create-Ubuntu-Client.ps1, 소스 사본 deploy/provision-ubuntu-client-vm.ps1. 문법 검사 완료이나 실행 검증 전이다. Windows UAC Start-Process RunAs가 '사용자가 작업을 취소했습니다'로 반환되어 VM/가상 스위치/IP는 아직 생성되지 않았다. 현재 공유 IP 문제는 미해결이며 허위 완료로 보고하지 않는다. 관리자 PowerShell에서 위 스크립트 실행이 필요하다. 현재 후보는 내부 스위치 SM-Test-Private, 게이트웨이 192.168.250.1/24, CLIENT 192.168.250.2, 2 CPU/시작 2GiB/동적 1~3GiB. 실행 후 VM 부팅·SSH·WSL SERVER 라우팅·NAT를 확인하고 장비 목록의 ubuntu-client를 새 IP/Ubuntu24.04/적절한 SSH 프로필로 갱신해야 한다. 이전 잘못 등록된 ubuntu-client는 현재 main WSL IP와 Ubuntu26.04/default 프로필을 가리키므로 검증 전 작업 실행 금지.

원래 Windows agent 갱신 설치도 이전 UAC 취소로 남아 있으며 사용자 허용 없이 우회하지 않는다. 자동화 일시정지 및 사용자 results.csv 미추적을 유지한다. 상세 D:/WSL/VM-Setup/README-KO.md.
